# windows安全系统2.0 — 项目描述

> 本文档面向 AI Agent / 新开发者，用于快速建立对项目结构、核心流程、约定与已知坑的整体认知。

## 1. 项目概述

一个基于**人脸识别 + 主动活体检测**的 Windows 安全系统原型。核心能力：

- **人脸录入**：摄像头采集人脸图像（支持引导式多角度采集 / 主动活体检测录入）
- **特征提取**：基于 InsightFace 提取 512 维人脸特征向量并持久化（`.npy` + `.json`）
- **人脸识别**：将待识别图像/实时视频流与已注册特征做余弦相似度比对
- **活体检测**：通过 5 个主动动作（左转/右转/抬头/眨眼/张嘴）判断是真人而非照片/翻拍

当前阶段重点在**人脸模块（FaceMoudle）**的流程跑通与性能优化，尚未接入系统级安全策略（如锁屏、访问控制等）。

## 4. 核心模块与 API

### 4.1 人脸录入 `faceInputer/inputter.py`

| 函数 | 作用 |
|---|---|
| `imgInputter()` | 文件选择对话框，返回图片路径（测试用） |
| `openCamera()` | 引导式采集 30 张（正面 10 + 左转/右转/抬头/眨眼/张嘴 各 4） |
| `openCameraWithLiveness(userName)` | 活体检测录入，5 动作通过后取平均特征，直接存 `.npy`+`.json` |
| `faceCheck(folderPath, maxWorkers)` | 多进程批量检测人脸，返回 `{路径: {hasFace,...}}` |
| `handleNoFace(checkResultsDict)` | 删除无脸图（Copy-on-Write，返回新字典） |
| `coverDict(originalDict, newDict)` | 安全覆盖共用字典（4 重校验） |

关键常量：`TARGET_CAPTURE_COUNT=30`、`CAPTURE_SAVE_DIR=cache/captured_photos`、`DET_SIZE=(480,480)`。

### 4.2 活体检测 `faceInputer/livenessDetector.py`

类 `LivenessDetector`：

| 方法 | 作用 |
|---|---|
| `runLivenessCheck(cap)` | 活体检测主流程（**双线程架构**，见 §7） |
| `checkAction(frame, actionName)` | 单线程动作判定（内部委托给下者） |
| `checkActionWithFaces(faces, frame, actionName)` | 复用已检测人脸对象做判定（不重复推理） |
| `collectBaselineEAR(cap, ...)` | 采集眨眼基准 EAR（失败自动重试） |
| `computeHeadPose(landmarks, imgShape)` | solvePnP 计算 Yaw/Pitch/Roll |
| `computeEAR(landmarks, eyeIndices)` | 眼睛纵横比 |
| `computeMAR(landmarks)` | 嘴巴纵横比 |

### 4.3 特征提取 `faceDetecter/faceDataGetter.py`

| 函数 | 作用 |
|---|---|
| `generateFaceFeature(userName, imgDir, maxWorkers)` | 主入口：批量提取→平均→归一化→保存 |
| `extractBatchFeatures(imgDir, maxWorkers)` | 多进程批量提取 512 维特征 |
| `computeMeanFeature(embeddings)` | 平均 + L2 归一化 |
| `saveFeatureNpy(feature, filePath)` / `saveFeatureJson(...)` | 保存特征（均 2 参数） |
| `cleanOldModelFiles(faceDataDir, userName)` | 清理同名用户旧特征（注意参数顺序） |

### 4.4 人脸识别 `facialRecognition/recognition.py`

| 函数 | 作用 |
|---|---|
| `recognizeFace(registeredNpyPath, img, threshold)` | 单特征图片识别 |
| `recognizeFaceMulti(registeredNpyPaths, img, threshold)` | 多特征比对，返回最佳匹配 |
| `runLivenessRecognize(registeredNpyPath, threshold)` | **活体检测 + 识别一体化**（摄像头） |
| `computeSimilarity(emb1, emb2)` | 余弦相似度 |
| `loadRegisteredFeature(npyPath)` | 加载注册特征 |

阈值：`DEFAULT_THRESHOLD = 0.4`。

## 5. 端到端流程

```
录入（faceInputer）
  ├─ 方式2 引导式采集：openCamera() 拍 30 张 → faceCheck → handleNoFace → coverDict
  │        ↓ 可用人脸图
  └─ 方式3 活体录入：openCameraWithLiveness() 一步到位（5动作 → 特征 → 保存）

特征提取（faceDetecter）
  generateFaceFeature() → 多进程提取 → 平均 → .npy/.json 存到 cache/faceData

识别（facialRecognition）
  ├─ 图片识别：recognizeFace() / recognizeFaceMulti()
  └─ 实时活体识别：runLivenessRecognize()（活体 → 特征 → 余弦比对）
```

## 6. 活体检测机制

- **动作序列**：`["左转", "右转", "抬头", "眨眼", "张嘴"]`（顺序固定）
- **判定依据**：InsightFace `buffalo_l` 的 `landmark_2d_106`（106 关键点）
  - 头部姿态：`solvePnP` + 6 个基准点 → Yaw/Pitch/Roll
  - 眨眼：EAR（眼睛纵横比）相对 baseline 下降
  - 张嘴：MAR（嘴巴纵横比）
- **当前阈值**（已放宽，避免正常用户超时）：
  - 左转 Yaw < -20°、右转 Yaw > 20°、抬头 Pitch > 15°
  - 眨眼 EAR 下降 > 20%（相对 baseline）、张嘴 MAR > 0.4
  - 每动作超时 3.0s、baseline 采集 1.5s

## 7. 关键架构决策与性能优化

1. **双线程活体检测**（`runLivenessCheck`）：
   - 主线程只做 `cap.read()` + `cv2.imshow()`（画面流畅）
   - 子线程从 `frame_queue`（maxsize=1）取帧推理，结果放 `result_queue`
   - 主线程非阻塞取结果判定，推理不再阻塞显示
   - `clearQueues()` 动作切换前清残留，`try/finally` 保证子线程终止
2. **轻量/完整模型分离**：
   - 动作检测只用 `detection + landmark_2d_106`（det_size=160），不加载 166MB 识别模型
   - 仅动作通过后懒加载 `recognition` 模型提取特征
3. **多进程特征提取**：`ProcessPoolExecutor` + `initializer` 每进程加载一次模型，绕过 GIL。
4. **中文路径兼容**：读图用 `np.fromfile` + `cv2.imdecode`，写图用 `cv2.imencode` + `tofile`。

## 8. 命名规范（硬性约定）

| 类型 | 规则 | 示例 |
|---|---|---|
| 函数/方法 | 首字母小写 + 后续音节首字母大写（camelCase） | `addFunction`、`openCamera` |
| 变量 | 全小写 + 下划线分隔（snake_case） | `add_number`、`img_path` |
| 类 | 首字母大写（PascalCase） | `AddClass`、`LivenessDetector` |
| 常量 | 全大写 | `DEFINENUMBER`、`TARGET_CAPTURE_COUNT` |

代码注释原则：能加就加，新功能/意义必须加；类/函数/方法/变量定义必须有注释；跨模块调用要注明调用位置与含义。

## 9. 环境配置

- 使用项目内虚拟环境 `.venv`，解释器路径：`.venv\Scripts\python.exe`
- **PyCharm 坑**：需确认 SDK 的 classPath 包含 `.venv/Lib/site-packages`，否则 `import insightface` 报 `No module named insightface`（见 bug-logs）
- 模型已在项目内 `FaceMoudle/moudleTrainner/models/buffalo_l/`，无需联网下载

## 10. 已知坑 / 注意事项（详见 docs/bug-logs）

1. `No module named insightface` → PyCharm SDK classPath 配置
2. `NotADirectoryError` → `faceCheck` 需区分单文件/目录
3. 多进程启动报 bootstrapping 错误 → 需 `if __name__ == '__main__'` 保护（spawn 模式）
4. 中文路径读写图片 → 必须用 `imdecode/imencode`，勿用 `cv2.imread/imwrite`
5. `saveFeatureNpy/Json` 为 2 参数 `(feature, filePath)`；`cleanOldModelFiles(faceDataDir, userName)` 注意参数顺序
6. 目录名是 `faceDetecter`、`moudleTrainner`（拼写特殊，勿按常规修正）

## 11. 模型文件说明（buffalo_l）

| 文件 | 用途 |
|---|---|
| `det_10g.onnx` | 人脸检测（SCRFD，输出 5 点关键点） |
| `2d106det.onnx` | 106 关键点检测（EAR/MAR/姿态计算） |
| `w600k_r50.onnx` | 人脸识别（512 维 embedding） |
| `1k3d68.onnx` / `genderage.onnx` | 本项目忽略（3D 关键点/年龄性别） |
